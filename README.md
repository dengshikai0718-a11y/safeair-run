# SafeAir Run｜慢跑場域環境查詢

純前端的響應式網頁原型（主程式為單一檔案 `index.html`）。依 **PM2.5、降雨機率、紫外線指數、體感溫度**，以三級燈號判斷台北跑點「現在適不適合出發」，並提供熱力圖、替代跑點推薦與背景監測通知。

- 🟢 適合出發　🟡 建議留意　🔴 不建議前往　⚪ 資料不足
- 無後端、無打包工具；唯一的外部程式依賴是 Leaflet 1.9.4（unpkg CDN，附 SRI 校驗）。
- 可雙擊 `index.html`（`file://`）以內建 Mock 數據完整操作；部署到 GitHub Pages（HTTPS）後可用真實定位與通知。

## 快速開始

### 直接開啟

雙擊 `index.html`（`file://`）即可預覽完整 UI，並以 Mock 數據操作。

> `file://` 下瀏覽器通常不提供定位、Service Worker 與系統通知，地點搜尋也可能被拒絕（沒有 Referer）。要測試這些請用下方本機伺服器或 GitHub Pages。

### 本機伺服器

使用 Node.js（預設 http://localhost:3000）：

```bash
npx serve .
```

使用 Python 3（預設 http://localhost:8000）：

```bash
python -m http.server 8000
```

> `localhost` 被瀏覽器視為安全來源，可在電腦上測試定位與通知。手機透過區網 IP（http://192.168.x.x）連線**不是**安全來源，定位與通知會被封鎖，請改用 GitHub Pages。

### GitHub Pages 零成本部署（手機實機 HTTPS 測試）

1. 將專案推上 GitHub（`index.html` 需位於 repo 根目錄）。
2. 進入 repo 的 **Settings → Pages**。
3. **Build and deployment → Source** 選 **Deploy from a branch**。
4. **Branch** 選 `main`、資料夾選 `/ (root)`，按 **Save**。
5. 約 1～2 分鐘後，頁面上方會顯示網址：`https://<帳號>.github.io/<repo 名稱>/`。
6. 用手機瀏覽器開啟該網址，允許「位置」權限；要測試通知請看 [背景監測與通知](#背景監測與通知)。

之後每次 `git push` 到 `main`，GitHub Pages 會自動重新部署。

### CARTO 底圖金鑰（部署後務必設定）

CARTO 底圖已改為需要（免費）API 金鑰，未帶金鑰會顯示「API KEY REQUIRED」浮水印圖磚。金鑰設定在 `index.html` 的 `CONFIG.CARTO_API_KEY`，底圖與標籤圖層網址都會自動加上 `?key=`。

由於這是純前端網頁，**金鑰會隨程式碼公開**。部署到 GitHub Pages 後請立即：

1. 登入 CARTO 後台，找到此 API 金鑰的設定。
2. 加入 Referer（允許網域）限制：`https://<帳號>.github.io/*`。
3. 若仍需在本機開發，可一併加入 `http://localhost:*`。注意：`file://` 雙擊開啟時瀏覽器不送 Referer，加上限制後可能無法載入底圖，請改用本機伺服器。
4. 若金鑰疑似被濫用，可在後台重新產生金鑰並更新 `CONFIG.CARTO_API_KEY`。

### 推薦規則（依對象區分）

- **跑點**（選取的跑點）：只有該跑點為 🟡／🔴 才顯示，標題「**替代跑點**」；列出 5 km 內燈號**嚴格較佳**的跑點（排除自己）。沒有候選：「附近暫無更佳跑點，建議改至室內運動」。
- **目前位置、搜尋地點、地圖選點**：一律顯示「**附近跑點**」，列出 5 km 內的跑點（不論燈號）。沒有跑點：「5 公里內沒有收錄的跑點」。
- 共通：先依燈號、再依距離（Haversine）排序，最多 3 筆；點擊即切換到該跑點。

## 操作方式

### 版面

- **寬螢幕（≥ 768px）**：左側 380px 側邊欄（搜尋 → 資訊卡 → 跑點列表 → 背景監測 → 資料模式），其餘為地圖。列表先依燈號、再依與你的距離排序（無定位時依名稱）。
- **窄螢幕（< 768px）**：全螢幕地圖；頂部浮動搜尋欄與設定鈕（資料模式、資料來源狀態、背景監測）；底部 **Bottom Sheet** 收合 140px、展開 80vh，可上下拖曳，也可點握把切換（鍵盤 Enter／Space 亦可）；展開後可看完整資訊卡與跑點列表。
- 地圖右下角「回到我的位置」；定位失敗以台北車站為中心、縮放 12，並提示「未取得定位」。
- 未選取任何對象時，資訊卡顯示「目前位置」的環境狀態；沒有定位時提示「點選地圖上的跑點，查看是否適合出發」。
- 點資訊卡右上角 ✕，或點一下地圖空白處，可取消選取。拖曳地圖不會被當成點擊。

### 搜尋

- 打字時只做**本機比對**（跑點、行政區），最多 5 筆，可用 ↑ ↓ Enter Esc 操作。輸入行政區名稱會縮放到該區全部跑點；輸入跑點名稱（可部分相符）會平移到該跑點並開啟資訊卡。
- 下拉最後一列是「搜尋地點：『輸入文字』」。**點擊該列，或沒有本機符合項目時按 Enter，才會送出外部地理編碼查詢**（不會邊打字邊查）。結果最多 5 筆，限定台灣、台北優先。
- 結果：地圖平移到該地點並放置深色水滴形搜尋圖釘；資訊卡內容與「目前位置」相同。結果在台北市界外顯示「目前僅支援台北市」，不計算燈號。查詢失敗或無結果顯示「找不到這個地點，試試地標或路名」。

### 地圖選點（不使用任何外部服務）

- **手機**：長按地圖約 500 ms。手指移動超過 10 px、提早放開、或出現第二指（縮放）都會取消，不會與拖曳衝突；放開時的那一次 click 會被忽略，不會被當成「點空白處取消選取」。已用 CSS 避免 iOS Safari 長按時跳出系統選單或選取文字。
- **電腦**：在地圖上按右鍵；雙擊放大維持預設。
- 畫面上永遠只有**一個**暫時圖釘，新的選點會取代舊的搜尋或選點圖釘。資訊卡標題「地圖選取位置」，副標為行政區，內容與「目前位置」相同。
- 行政區判定為離線近似：市界內取距離最近的 12 個行政區中心點，交界附近可能差一區；僅用於顯示與通知冷卻分組。

### 資料模式與 Demo 網址

側邊欄底部（窄螢幕在設定選單）可切換「即時資料／正常／高空汙／大雨曝曬」。也可用網址參數直接以情境開啟（不發出任何資料請求）：

```
index.html?mode=normal      # 正常：青年公園 🔴、大佳河濱公園 🟡、其餘 🟢
index.html?mode=pollution   # 高空汙：大佳河濱公園 🟡、其餘 PM2.5 ≥ 35.5 🔴
index.html?mode=storm       # 大雨曝曬：大佳、花博降雨 > 60%，其餘 UVI ≥ 8（全部 🔴）
```

### Nominatim 使用定位聲明

本專案是**低流量原型**，已實作「按下才查詢」、1.1 秒節流與記憶體快取；**不得用於批次或自動定期查詢**；若未來正式公開或使用量提高，**必須改用付費或自架的地理編碼服務**（改 `CONFIG.GEOCODER.url` 並調整解析即可）。專案擁有者已閱讀其使用政策，知情並決定使用，並負責遵守。

### PM2.5 資料清洗規則

1. 只保留台北市範圍框內的測站（經度 121.45–121.67、緯度 24.96–25.21）。
2. 排除 PM2.5 **≤ 0** 或 **> 500** μg/m³ 的測站（LASS 實測約半數測站回報 0，多為感測異常，會嚴重拉低 IDW 估算）。
3. 排除更新時間距今超過 60 分鐘的測站。
4. 有效測站 < 2 站或請求失敗（逾時 8 秒）時，自動改用內建 Mock 數據，並顯示「離線／展示模式」；滑鼠移到標記上或點擊可看原因。

檢查資料來源欄位（不會印出完整 JSON，會輸出「0 值測站數」）：

```bash
python3 tools/pm25_summary.py https://pm25.lass-net.org/data/last-all-airbox.json
```

## 判定規則、IDW 與熱力圖

### 三級門檻（連續區間）

| 指標 | 🟢 | 🟡 | 🔴 |
| :--- | :--- | :--- | :--- |
| PM2.5（μg/m³） | ≤ 15.4 | > 15.4 且 < 35.5 | ≥ 35.5 |
| 降雨機率（%） | ≤ 30 | > 30 且 ≤ 60 | > 60 |
| 紫外線指數 | ≤ 5.0 | > 5.0 且 < 8.0 | ≥ 8.0 |
| 體感溫度（°C） | 10.0–30.0 | 5.0–< 10.0 或 > 30.0–33.0 | < 5.0 或 > 33.0 |

主因指標：先比燈號，同燈號依 PM2.5 > 降雨 > 紫外線 > 體感溫度；體感溫度分過熱／過冷，建議文案不同。

### IDW（跑點與熱力圖共用 `idwEstimate`）

- 數值一律使用**全部有效測站**的反距離加權（p = 2）；最近測站 < 50 m 時直接採用該測站數值。
- 距離只決定顯示、不影響數值：最近測站 > 3 km，熱力圖留白（市界內畫淡灰斜線）；> 5 km，資訊卡標示「附近無測站，以全市測站估算」。

### 熱力圖

- 在台北市外框的外接矩形內以 75 m 細格逐格呼叫 `idwEstimate`（不先算 300 m 網格再內插：網格節點不會剛好落在測站上，測站附近的峰值會被平均壓低一級），依門檻離散上色，再以市界裁切，用 `L.imageOverlay`（透明度 0.35）疊在地圖上。
- 圖例只描述 PM2.5 濃度高低（PM2.5 低／中／高），不使用跑點燈號用語，避免「紅色不建議前往標記」壓在「適合出發」綠區上的矛盾。窄螢幕預設為單行小圖例，點一下展開完整說明。
- 只在資料更新時重算（Chrome CPU 4× 降速下，30／80／150 站分別約 0.1／0.2／0.3 秒）；開關只切換圖層顯示。

## 背景監測與通知

- 預設關閉。開啟時請求通知權限；被拒絕、不支援（例如網址不是 HTTPS／localhost）時改為只顯示頁面橫幅，並說明原因。
- 每 10 分鐘（隨資料更新；手動切換資料模式也會立即檢查）比較「目前位置」的燈號：**綠 → 黃/紅、黃 → 紅** 時提醒；第一次檢查只記錄基準。沒有定位顯示「需定位才能監測」。
- 提醒內容為狀態、主因與建議，同時送出系統通知與可關閉的橫幅（最多同時 3 則）。
- 同一行政區 60 分鐘內不重複提醒；冷卻紀錄存於 `localStorage`（不可用時退回記憶體）。「立即測試通知」同樣遵守冷卻，冷卻中顯示「冷卻中，剩 N 分鐘」；「清除冷卻紀錄」可重置。沒有定位時，測試通知以選取的跑點（或第一個跑點）示範。
- 想快速看到效果：開啟監測後（需有定位），把資料模式從「正常」切到「高空汙」。
- **`sw.js`**：手機瀏覽器（Android Chrome、iOS）不允許頁面直接 `new Notification`，必須經由 Service Worker 的 `showNotification`，所以多了一個只負責顯示通知與點擊回到頁面的 `sw.js`（不快取、不攔截請求）。`file://` 無法註冊 Service Worker，會自動退回頁面直接通知或橫幅。

### iPhone 通知設定

需 **iOS 16.4 以上**：先用 Safari 開啟網址 →「分享 → 加入主畫面」→ 從**主畫面圖示**開啟（以 App 方式運作）→ 設定選單開啟背景監測並允許通知。在 Safari 分頁內無法使用系統通知（頁面內橫幅仍可用，介面會提示）。

專案含 `manifest.json`（standalone、主題色 #10B981、背景色 #F8FAFC）與 `icons/`（192／512／apple-touch-icon）。manifest 只在 http(s) 下動態加入；`file://` 不載入，以免 Chrome 在 Console 印出 CORS 錯誤。

## 已知限制

- **頁面關閉後無法監測**：純網頁在分頁／App 被關閉後無法執行。iOS 上 App 切到背景後網頁很快被凍結，計時器與 Service Worker 都無法長時間運作，回到前景時才會補做檢查。
- **LASS 實際上不可用**：2026-11 實測，回應沒有 `Access-Control-Allow-Origin`（瀏覽器無法讀取），且資料停在 2026-09-01，因此「即時資料」模式的 PM2.5 會降級為 Mock 並說明原因；氣象（Open-Meteo）可正常取得。`PM25_SOURCES` 已預留 STA adapter 空函式（SensorThings API，憑證過期、尚未實測 CORS，待重新測試）。
- **Console 已知錯誤（僅「即時資料」模式）**：由瀏覽器網路層直接輸出，網頁程式無法攔截；程式已自動降級為展示數據。三種 Mock 情境下 Console 應為零錯誤、零警告。

  | 錯誤訊息 | 來源 | 原因 |
  | :--- | :--- | :--- |
  | `Access to fetch at 'https://pm25.lass-net.org/...' has been blocked by CORS policy`、`net::ERR_FAILED` | LASS 空氣盒子 | 伺服器回應未帶 `Access-Control-Allow-Origin` 標頭（另：資料自 2026-09-01 起停止更新） |
  | `429 (Too Many Requests)` | Open-Meteo | 同一對外 IP 請求過多被限流（雲端主機、共用網路較常見，通常稍後即恢復） |
  | CORS 錯誤／`629` 或 `429` | Nominatim（地點搜尋） | 只會在使用「搜尋地點」且被限流或用 `file://` 開啟時出現；被限流時錯誤頁不含 CORS 標頭，介面會顯示查詢失敗訊息 |

- **地點搜尋依賴公用服務**：容量有限、需 Referer（`file://` 不可用），詳見上方使用定位聲明。
- **行政區判定與市界為近似值**：行政區取最近中心點，市界簡化到約 80 m，皆不是官方界線。
- **熱力圖只反映 PM2.5**：跑點燈號看四項指標，兩者不一定一致（圖例已明講）。
- **Mock 數據僅供展示**：「正常」情境的青年公園周邊測站數值為了讓熱力圖形成可見的紅色區塊而刻意調高。
- **iOS 通知需加入主畫面**；iOS 版本需 16.4 以上；通知無法保證在背景持續監測期間送達。

## 未來可擴充項目

1. **伺服器 Web Push**：讓 App 完全關閉也能收到通知。需要 VAPID 金鑰、Service Worker `push` 事件、前端訂閱流程，以及後端（儲存訂閱與粗略位置、每 10 分鐘抓資料並套用同一套判定、用加密 Web Push 協定送出）。免費方案可考慮 Cloudflare Workers＋Cron Trigger＋KV/D1。需評估隱私（儲存裝置端點與位置，建議只存行政區代碼並設保存期限）與維運成本，預估 3–5 個工作天（含 iOS 實機除錯）。
2. **真實 PM2.5 資料來源**：重新測試 STA（SensorThings API）adapter；或評估環境部（moenv）資料（需金鑰）、改走自架代理或排程快取，以取得「免金鑰、支援 CORS、可依範圍查詢」的穩定來源，解除 LASS 無法使用的限制。
3. **擴充到台灣北部**：把 `RUN_SPOTS` 擴充到 25 個以上並涵蓋新北、基隆、桃園；市界改為多個縣市界或改用行政區面資料；`BBOX`、行政區判定與 `CONFIG.GEOCODER` 的範圍同步調整。
4. **更精確的行政區判定**：用官方行政區面資料（例如內嵌簡化後的 12 區多邊形）取代最近中心點。
5. **跑點評分與路線**：加入空氣品質預報、依時段推薦出發時間，或與路線資料結合。
6. **更多氣象來源與備援**：中央氣象署開放資料（需金鑰）作為 Open-Meteo 的備援。

```js
SafeAir.runTests()
```

```js
SafeAir.evaluate({ pm25: 12, rain: 40, uvi: 9, feels: 25 })
```
