# SafeAir Run｜慢跑場域環境查詢

純前端、單一檔案（`index.html`）的響應式網頁原型。依 PM2.5、降雨機率、紫外線指數、體感溫度，以三級燈號判斷台北跑點是否適合出發。

- 唯一外部依賴：Leaflet 1.9.4（unpkg CDN）
- 圖資：© OpenStreetMap 貢獻者、© CARTO
- 資料來源：LASS 空氣盒子（PM2.5）、Open-Meteo（氣象）；無法取得時自動切換為內建 Mock 數據

## 快速預覽

直接在電腦上雙擊 `index.html`（`file://`）即可預覽完整 UI，並以 Mock 數據操作。

> `file://` 環境下，瀏覽器可能不提供定位與 Web Notification。要測試這兩項，請用下方本機伺服器或 GitHub Pages（HTTPS）。

## 本機伺服器

在專案資料夾執行以下任一指令，再用瀏覽器開啟終端機顯示的網址。

使用 Node.js（`npx serve`，預設 http://localhost:3000）：

```bash
npx serve .
```

使用 Python 3（預設 http://localhost:8000）：

```bash
python -m http.server 8000
```

> `localhost` 被瀏覽器視為安全來源，可在電腦上測試定位與通知。手機透過區網 IP（http://192.168.x.x）連線則**不是**安全來源，定位與通知會被封鎖，請改用 GitHub Pages。

## GitHub Pages 零成本部署（手機實機 HTTPS 測試）

1. 將專案推上 GitHub（`index.html` 需位於 repo 根目錄）。
2. 進入 repo 的 **Settings → Pages**。
3. **Build and deployment → Source** 選 **Deploy from a branch**。
4. **Branch** 選 `main`、資料夾選 `/ (root)`，按 **Save**。
5. 約 1～2 分鐘後，頁面上方會顯示網址：`https://<帳號>.github.io/<repo 名稱>/`。
6. 用手機瀏覽器開啟該網址：
   - 允許「位置」權限 → 測試真實定位與「目前位置」環境狀態。
   - 開啟「背景監測」並允許通知 → 測試 Web Notification。
   - iPhone（iOS 16.4 以上）的 Safari 只允許「已加入主畫面」的網頁發送通知：請先點 **分享 → 加入主畫面**，再從主畫面圖示開啟。

之後每次 `git push` 到 `main`，GitHub Pages 會自動重新部署。

## CARTO 底圖金鑰（部署後務必設定）

CARTO 底圖已改為需要（免費）API 金鑰，未帶金鑰時會顯示「API KEY REQUIRED」浮水印圖磚。金鑰設定在 `index.html` 的 `CONFIG.CARTO_API_KEY`，底圖與標籤圖層網址都會自動加上 `?key=`。

由於這是純前端網頁，**金鑰會隨程式碼公開**（repo 與 GitHub Pages 皆可看到）。部署到 GitHub Pages 後，請立即：

1. 登入 CARTO 後台，找到此 API 金鑰的設定。
2. 加入 Referer（允許網域）限制：`https://<帳號>.github.io/*`。
3. 若仍需在本機開發，可一併加入 `http://localhost:*`。注意：`file://` 雙擊開啟時瀏覽器不送 Referer，加上限制後本機雙擊可能無法載入底圖，請改用本機伺服器。
4. 若金鑰疑似被濫用，可在後台重新產生金鑰並更新 `CONFIG.CARTO_API_KEY`。

## 資料模式與 Demo 網址

側邊欄底部可切換「即時資料 / 正常 / 高空汙 / 大雨曝曬」。也可用網址參數直接以情境開啟（不發出任何資料請求）：

```
index.html?mode=normal      # 正常：青年公園 🔴、大佳河濱公園 🟡、其餘 🟢
index.html?mode=pollution   # 高空汙：大佳河濱公園 🟡、其餘 PM2.5 ≥ 35.5 🔴
index.html?mode=storm       # 大雨曝曬：大佳、花博降雨 > 60%，其餘 UVI ≥ 8
```

## 地點搜尋（地理編碼）

搜尋欄除了內建跑點與行政區，也能搜尋任意地點（地標、路名、捷運站、地址），使用 **OpenStreetMap Nominatim** 公用服務（`https://nominatim.openstreetmap.org`，免金鑰、支援 CORS）。

- **兩段式互動**：打字時只做本機比對（跑點、行政區），下拉最後一列為「搜尋地點：『輸入文字』」；**點擊該列，或沒有可選的本機項目時按 Enter，才會送出查詢**，不會邊打字邊查。結果最多 5 筆，限定台灣、台北範圍優先，台北市內的排在前面。
- **結果**：地圖平移到該地點並放置深色水滴形搜尋標記；資訊卡內容與「目前位置」相同（四項數值、燈號、建議、換點推薦）。結果在台北市界外時顯示「目前僅支援台北市」，不計算燈號。查詢失敗或無結果顯示「找不到這個地點，試試地標或路名」。
- **使用條款**（[Nominatim Usage Policy](https://operations.osmfoundation.org/policies/nominatim/)）：
  - 使用者操作直接觸發的搜尋可使用；**禁止自動完成**（本專案不會）。
  - 每秒最多 1 次請求（程式強制間隔 ≥ 1.1 秒），相同查詢只查一次（記憶體快取）。
  - 須以 `Referer` 或 `User-Agent` 辨識應用程式。瀏覽器無法自訂 User-Agent，靠 `Referer` 辨識，所以請用 **localhost 或 GitHub Pages** 開啟；以 `file://` 雙擊開啟時沒有 Referer，服務可能拒絕，此時會顯示查詢失敗訊息。
  - 公用服務容量有限，使用者數量多時應改用自架或付費服務；政策也要求應用程式能在服務方要求時切換來源（改 `CONFIG.GEOCODER.url` 即可，不需改程式邏輯）。
- **使用定位（本專案的用法聲明）**：本專案是**低流量原型**，已實作「按下才查詢」、1.1 秒節流與記憶體快取；**不得用於批次或自動定期查詢**；若未來正式公開或使用量提高，**必須改用付費或自架的地理編碼服務**（改 `CONFIG.GEOCODER.url` 並調整解析即可）。專案擁有者已閱讀上述使用政策，知情並決定使用，並負責遵守。
- **資料授權**：搜尋結果與台北市界皆來自 OpenStreetMap，採 ODbL 授權，須標示「© OpenStreetMap 貢獻者」（地圖右下角已標示）。
- 被限流時服務會回傳不含 CORS 標頭的錯誤頁，瀏覽器 Console 會出現一則 CORS／429 類錯誤並顯示查詢失敗訊息；這只會在使用地點搜尋且被限流時發生，三種 Mock 情境不受影響。

## 地圖選點（不使用任何外部服務）

- **手機**：在地圖上長按約 500 ms。手指移動超過 10 px、提早放開、或出現第二指（縮放）都會取消，因此不會與拖曳地圖衝突；長按放開時的那一次 click 會被忽略，不會被當成「點空白處取消選取」。已用 CSS（`-webkit-touch-callout: none`、`user-select: none`）避免 iOS Safari 長按時跳出系統選單或選取文字，並擋掉 Android 的長按選單。
- **電腦**：在地圖上按右鍵。雙擊放大維持 Leaflet 預設；點一下空白處仍是取消選取。
- 在該點放置與「搜尋地點」相同樣式的圖釘；畫面上永遠只有一個暫時圖釘，新的選點會取代舊的搜尋或選點圖釘。
- 資訊卡標題為「地圖選取位置」，副標為行政區，內容與「目前位置」相同（四項數值、燈號、建議、換點推薦；共用 `idwEstimate`，氣象只替該點補查一次）。市界外顯示「目前僅支援台北市」，不計算燈號。
- **行政區判定**（離線、近似）：台北市界內取距離最近的 12 個行政區中心點；交界附近可能差一區，僅用於顯示與通知冷卻分組，不是官方界線。

## 背景監測與通知

- 預設關閉。開啟時請求通知權限；被拒絕、不支援（例如網址不是 HTTPS / localhost）時改為只顯示頁面橫幅，並說明原因。
- 每 10 分鐘（隨資料更新，手動切換資料模式也會立即檢查）比較「目前位置」的燈號：**綠 → 黃/紅、黃 → 紅** 時提醒；第一次檢查只記錄基準，不提醒。沒有定位時顯示「需定位才能監測」。
- 提醒內容為狀態、主因與建議，同時送出系統通知與可關閉的橫幅。
- 同一行政區 60 分鐘內不重複提醒，冷卻紀錄存於 `localStorage`（不可用時退回記憶體）。「立即測試通知」同樣遵守冷卻，冷卻中顯示「冷卻中，剩 N 分鐘」；「清除冷卻紀錄」可重置。沒有定位時，測試通知以選取的跑點（或第一個跑點）示範。
- **限制**：純網頁在頁面（分頁 / PWA）被關閉後無法執行，只能在頁面開著（可在背景）時監測；手機瀏覽器背景分頁的計時器可能被節流。
- **`sw.js`**：手機瀏覽器（Android Chrome）不允許頁面直接 `new Notification`，必須經由 Service Worker 的 `showNotification`，所以多了一個只負責顯示通知與點擊回到頁面的 `sw.js`（不快取、不攔截請求）。`file://` 無法註冊 Service Worker，會自動退回頁面直接通知或橫幅。iPhone 需 iOS 16.4 以上並「加入主畫面」後從圖示開啟。
- 想快速看到效果：開啟監測後，用資料模式從「正常」切到「高空汙」（需有定位），下次檢查即會提醒。

## 換點推薦

資訊卡對象為 🟡／🔴 時（選取的跑點、目前位置、搜尋位置皆適用）顯示「附近更佳跑點」：5 km 內（Haversine）燈號較佳的跑點，燈號較佳者在前、同燈號依距離，最多 3 筆；點擊即切換到該跑點。沒有候選時顯示「附近暫無更佳跑點，建議改至室內運動」。

## 介面操作

- **搜尋**：先比對內建資料（地點搜尋見上節）。輸入跑點名稱（可部分相符）會平移到該跑點並開啟資訊卡；輸入行政區名稱會縮放到該區全部跑點。下拉最多 5 筆，可用 ↑ ↓ Enter Esc 操作；無結果顯示「找不到符合的跑點或行政區」。
- **資訊卡**：燈號、名稱、行政區、一句建議，以及 PM2.5／降雨機率／紫外線／體感溫度 2×2 格（各自有燈號圓點，缺值顯示「—」）、更新時間與資料來源狀態；資料不全顯示「部分資料暫缺」，最近測站超過 5 km 顯示「附近無測站，以全市測站估算」。未選取跑點時顯示「目前位置」的環境狀態；也沒有定位時提示點選跑點。點資訊卡右上角 ✕ 或地圖空白處可取消選取。
- **寬螢幕（≥ 768px）**：左側 380px 側邊欄（搜尋 → 資訊卡 → 跑點列表 → 資料模式）。列表先依燈號、再依距離排序（無定位時依名稱）。
- **窄螢幕**：全螢幕地圖，頂部浮動搜尋欄與設定鈕（資料模式、資料來源狀態）。底部 Bottom Sheet 收合 140px／展開 80vh，可上下拖曳、點握把切換（鍵盤 Enter／Space 也可）；展開後可看完整資訊卡與跑點列表。熱力圖圖例預設為單行小圖例，點一下展開完整說明。

## PM2.5 熱力圖

地圖右上角（窄螢幕在搜尋列下方右側）的圖層按鈕可開關 PM2.5 熱力圖，開啟時顯示圖例。

- 圖例只描述 PM2.5 濃度（低 ≤ 15.4／中 15.5–35.4／高 ≥ 35.5），不使用跑點燈號用語；跑點是否適合出發以燈號為準。
- **IDW 規則只有一套**：熱力圖與跑點共用 `idwEstimate`，數值一律使用全部有效測站的反距離加權（p = 2）；最近測站 < 50 m 時直接採用該測站數值。
- 距離只決定顯示方式、不影響數值：最近測站 > 3 km，熱力圖留白（市界內畫淡灰斜線）；最近測站 > 5 km，資訊卡標示「附近無測站，以全市測站估算」。
- 在台北市外框的外接矩形內以 75 m 細格逐格計算（不先算 300 m 網格再內插：網格節點不會剛好落在測站上，測站附近的峰值會被平均壓低一級），依 PM2.5 門檻離散上色，再以市界裁切，用 `L.imageOverlay`（透明度 0.35）疊在地圖上。
- 只在資料更新時重算（Chrome CPU 4× 降速下，30 / 80 / 150 站分別約 0.1 / 0.2 / 0.3 秒），開關只切換圖層顯示。
- 市界取自 OpenStreetMap 臺北市行政邊界（© OpenStreetMap 貢獻者，ODbL），簡化至約 80 m 容差後內嵌（沿淡水河、新店溪、景美溪），只用於裁切，不可當作行政區判定。
- `SafeAir.runTests()` 包含兩項熱力圖一致性檢查：每個跑點位置的熱力圖等級 = 該跑點 PM2.5 單項燈號；固定種子抽 50 個市界內座標，熱力圖等級 = `idwEstimate` 等級。

## 資料清洗規則（PM2.5 測站）

1. 只保留台北市範圍框內的測站（經度 121.45–121.67、緯度 24.96–25.21）。
2. 排除 PM2.5 **≤ 0** 或 **> 500** μg/m³ 的測站（LASS 實測約半數測站回報 0，多為感測異常，會嚴重拉低 IDW 估算）。
3. 排除更新時間距今超過 60 分鐘的測站。
4. 有效測站 < 2 站或請求失敗（逾時 8 秒）時，自動改用內建 Mock 數據，並顯示「離線 / 展示模式」；滑鼠移到標記上或點擊可看原因。

檢查資料來源欄位（不會印出完整 JSON）：

```bash
python3 tools/pm25_summary.py https://pm25.lass-net.org/data/last-all-airbox.json
```

## Console 已知錯誤（僅「即時資料」模式）

三種 Mock 情境下 Console 應為零錯誤、零警告。「即時資料」模式下可能出現以下兩類錯誤，它們由瀏覽器網路層直接輸出，網頁程式無法攔截；程式已自動降級為展示數據，不影響操作：

| 錯誤訊息 | 來源 | 原因 |
| :--- | :--- | :--- |
| `Access to fetch at 'https://pm25.lass-net.org/...' has been blocked by CORS policy`、`net::ERR_FAILED` | LASS 空氣盒子 | 伺服器回應未帶 `Access-Control-Allow-Origin` 標頭，瀏覽器禁止網頁讀取（另：資料自 2026-09-01 起停止更新） |
| `429 (Too Many Requests)` | Open-Meteo | 同一對外 IP 請求過多被限流（雲端主機、共用網路較常見，通常稍後即恢復） |
| CORS 錯誤／`629` 或 `429` | Nominatim（地點搜尋） | 只會在使用「搜尋地點」且被限流或用 `file://` 開啟時出現；被限流時錯誤頁不含 CORS 標頭，介面會顯示查詢失敗訊息 |

## 判定測試

在瀏覽器 Console 執行：

```js
SafeAir.runTests()
```

會測試四項指標的門檻邊界值（15.4 / 15.5 / 35.5、30 / 31 / 60 / 61、5.0 / 8.0、5 / 10 / 30 / 33）、總體判定、缺值處理、主因優先順序，以及狀態文字色的 WCAG AA 對比度，並回報通過數。也可單獨呼叫：

```js
SafeAir.evaluate({ pm25: 12, rain: 40, uvi: 9, feels: 25 })
```
