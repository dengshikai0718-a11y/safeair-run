# SafeAir Run｜慢跑場域環境查詢

純前端的響應式網頁原型（主程式為單一檔案 `index.html`）。依 **PM2.5、降雨機率、紫外線指數、體感溫度**，以三級燈號判斷台北跑點「現在適不適合出發」，並提供熱力圖、替代跑點推薦與背景監測通知。

- 🟢 適合出發　🟡 建議留意　🔴 不建議前往　⚪ 資料不足
- 無後端、無打包工具；唯一的外部程式依賴是 Leaflet 1.9.4（unpkg CDN，附 SRI 校驗）。
- 可雙擊 `index.html`（`file://`）以內建 Mock 數據完整操作；部署到 GitHub Pages（HTTPS）後可用真實定位與通知。

## 快速開始

### 直接開啟

雙擊 `index.html`（`file://`）即可預覽完整 UI，並以 Mock 數據操作。

> `file://` 下瀏覽器通常不提供定位、Service Worker 與系統通知，地點搜尋也可能被拒絕（沒有 Referer）。要測試這些請用下方本機伺服器或 GitHub Pages。
>
> **注意**：CARTO 金鑰限制網域後（見下方「CARTO 底圖金鑰」），`file://` 將看不到底圖，開發與 Demo 請改用 GitHub Pages 網址或 `npx serve .`。

### 本機伺服器

使用 Node.js（預設 http://localhost:3000）：

```bash
npx serve .
```

使用 Python 3（預設 http://localhost:8000）：

```bash
python -m http.server 8000
```

> `localhost` 被瀏覽器視為安全來源，可在電腦上測試定位與通知。手機透過區網 IP（http://192.168.x.x）連線**不是**安全來源，定位與通知會被封鎖，請改用 GitHub Pages。

### GitHub Pages 零成本部署（手機實機 HTTPS 測試）

網站由 GitHub Actions（`.github/workflows/pages.yml`）部署，部署時同時抓取環境部 PM2.5 資料（見 [資料來源與授權](#資料來源與授權)）。

1. 將專案推上 GitHub（`index.html` 需位於 repo 根目錄）。
2. 到 repo 的 **Settings → Secrets and variables → Actions**，新增 Secret `MOENV_API_KEY`（環境部環境資料開放平臺的會員 API 金鑰）。
3. 進入 **Settings → Pages**，**Build and deployment → Source** 選 **GitHub Actions**。
4. 到 **Actions** → 「部署網站與 PM2.5 資料」→ **Run workflow**（之後 push 到 `main` 與每小時第 15、45 分會自動執行）。
5. 完成後網址為 `https://<帳號>.github.io/<repo 名稱>/`，PM2.5 資料在 `…/data/pm25.json`。
6. 用手機瀏覽器開啟該網址，允許「位置」權限；要測試通知請看 [背景監測與通知](#背景監測與通知)。

> **排程會被自動停用**：repo 連續 60 天沒有任何活動時，GitHub 會停用排程並寄信通知。到 **Actions** → 選該 workflow → **Enable workflow** 即可恢復。執行失敗時 GitHub 也會寄信，偶爾失敗沒關係（網頁沿用舊資料，超過 3 小時才降級為 Mock）。

### CARTO 底圖金鑰（部署後務必設定）

CARTO 底圖已改為需要（免費）API 金鑰，未帶金鑰會顯示「API KEY REQUIRED」浮水印圖磚。金鑰設定在 `index.html` 的 `CONFIG.CARTO_API_KEY`，底圖與標籤圖層網址都會自動加上 `?key=`。

由於這是純前端網頁，**金鑰會隨程式碼公開**。部署到 GitHub Pages 後請立即：

1. 登入 CARTO 後台，找到此 API 金鑰的設定。
2. 加入 Referer（允許網域）限制：`https://<帳號>.github.io/*`。
3. 若仍需在本機開發，可一併加入 `http://localhost:*`。
4. **設定 Referer 限制後，本機以 `file://` 雙擊開啟將看不到底圖**（瀏覽器不送 Referer，CARTO 會拒絕）。開發與 Demo 請改用 GitHub Pages 網址，或用 `npx serve .` 開啟（需把 `http://localhost:*` 加入允許清單）。
5. 若金鑰疑似被濫用，可在後台重新產生金鑰並更新 `CONFIG.CARTO_API_KEY`。

### 推薦規則（依對象區分）

- **跑點**（選取的跑點）：只有該跑點為 🟡／🔴 才顯示，標題「**替代跑點**」；列出 5 km 內燈號**嚴格較佳**的跑點（排除自己）。沒有候選：「附近暫無更佳跑點，建議改至室內運動」。
- **目前位置、搜尋地點、地圖選點**：一律顯示「**附近跑點**」，列出 5 km 內的跑點（不論燈號）。沒有跑點：「5 公里內沒有收錄的跑點」。
- 共通：先依燈號、再依距離（Haversine）排序，最多 3 筆；點擊即切換到該跑點。

## 操作方式

### 版面

- **寬螢幕（≥ 768px）**：左側 380px 側邊欄（搜尋 → 資訊卡 → 跑點列表 → 背景監測 → 資料模式），其餘為地圖。列表先依燈號、再依與你的距離排序（無定位時依名稱）。
- **窄螢幕（< 768px）**：全螢幕地圖；頂部浮動搜尋欄與設定鈕（資料模式、資料來源狀態、背景監測）；底部 **Bottom Sheet** 收合 140px、展開 80vh，可上下拖曳，也可點握把切換（鍵盤 Enter／Space 亦可）；展開後可看完整資訊卡與跑點列表。
- 地圖右下角「回到我的位置」；定位失敗以台北車站為中心、縮放 12，並提示「未取得定位」。
- 未選取任何對象時，資訊卡顯示「目前位置」的環境狀態；沒有定位時提示「點選地圖上的跑點，查看是否適合出發」。
- 點資訊卡右上角 ✕，或點一下地圖空白處，可取消選取。拖曳地圖不會被當成點擊。

### 搜尋

- 打字時只做**本機比對**（跑點、行政區），最多 5 筆，可用 ↑ ↓ Enter Esc 操作。輸入行政區名稱會縮放到該區全部跑點；輸入跑點名稱（可部分相符）會平移到該跑點並開啟資訊卡。
- 下拉最後一列是「搜尋地點：『輸入文字』」。**點擊該列，或沒有本機符合項目時按 Enter，才會送出外部地理編碼查詢**（不會邊打字邊查）。結果最多 5 筆，限定台灣、台北優先。
- 結果：地圖平移到該地點並放置深色水滴形搜尋圖釘；資訊卡內容與「目前位置」相同。結果在台北市界外顯示「目前僅支援台北市」，不計算燈號。查詢失敗或無結果顯示「找不到這個地點，試試地標或路名」。

### 地圖選點（不使用任何外部服務）

- **手機**：長按地圖約 500 ms。手指移動超過 10 px、提早放開、或出現第二指（縮放）都會取消，不會與拖曳衝突；放開時的那一次 click 會被忽略，不會被當成「點空白處取消選取」。已用 CSS 避免 iOS Safari 長按時跳出系統選單或選取文字。
- **電腦**：在地圖上按右鍵；雙擊放大維持預設。
- 畫面上永遠只有**一個**暫時圖釘，新的選點會取代舊的搜尋或選點圖釘。資訊卡標題「地圖選取位置」，副標為行政區，內容與「目前位置」相同。
- 行政區判定為離線近似：市界內取距離最近的 12 個行政區中心點，交界附近可能差一區；僅用於顯示與通知冷卻分組。

### 我的最愛

- **可加入**：內建跑點、搜尋地點、地圖選點（長按／右鍵）；**不能加入**：「目前位置」（位置會變動）、台北市界外的地點（提示「目前僅支援台北市」）。
- **加入／移除**：資訊卡標題旁的 ☆／★，點一下加入或移除。內建跑點直接加入（名稱沿用跑點名稱）；搜尋地點與地圖選點加入時要先命名（不可空白、最多 20 字；輸入框預設空白，以 placeholder 提示「為這個地點命名（例如：家附近）」）。自選點位之後可點資訊卡上的鉛筆改名（改名時預填目前名稱）。窄螢幕打開命名表單時 Bottom Sheet 會自動展開。
- **上限 5 個**：已滿時 ☆ 顯示為停用外觀，點擊或資訊卡內提示「最愛已滿（5 個），請先移除一個」。
- **顯示**：打開 App 時預設仍是「目前位置」。側邊欄與 Bottom Sheet（展開後）在「目前位置」資訊卡下方、「跑點列表」上方有「我的最愛」區塊：每列顯示燈號（色彩＋圖示＋文字）、名稱、與你的距離，依加入順序排列；點一下切換到該點位並展開資訊卡。沒有最愛時顯示「點資訊卡上的 ☆，把常去的地點加入最愛」。
- **地圖**：內建跑點加入後，標記右上角多一顆靛藍色小星號；自選點位以靛藍色星形標記常駐顯示（右下角小圓點為目前燈號），點擊開啟資訊卡。自選點位的資訊卡與「搜尋地點」相同（四項數值、燈號、建議、「附近跑點」）。
- **計算**：自選點位加入與跑點同一次 Open-Meteo 批次查詢，PM2.5 共用 `idwEstimate`。
- **儲存**：`localStorage`（鍵 `safeair.favorites.v1`，內容含版本號 `v`，方便日後搬到帳號系統）。**最愛只存在這台裝置與這個瀏覽器；iPhone 主畫面 App 與 Safari 的最愛是分開的**（設定選單與最愛區塊都有說明）。儲存空間不可用（無痕、停用）時退回記憶體並提示「最愛無法保存」，關閉頁面後會消失。載入時會丟棄格式不對、已不存在的跑點、市界外或名稱無效的項目。
- **不在這個版本**：匯出／匯入、背景監測改為監測最愛、帳號同步（見「未來可擴充項目」）。

### 資料模式與 Demo 網址

側邊欄底部（窄螢幕在設定選單）可切換「即時資料／正常／高空汙／大雨曝曬」。也可用網址參數直接以情境開啟（不發出任何資料請求）：

```
index.html?mode=normal      # 正常：青年公園 🔴、大佳河濱公園 🟡、其餘 🟢
index.html?mode=pollution   # 高空汙：大佳河濱公園 🟡、其餘 PM2.5 ≥ 35.5 🔴
index.html?mode=storm       # 大雨曝曬：大佳、花博降雨 > 60%，其餘 UVI ≥ 8（全部 🔴）
```

### PM2.5 資料流程與清洗規則

```
環境部 API ──(每小時第 45 分，GitHub Actions，帶 MOENV_API_KEY)──▶ tools/fetch_moenv.py ──▶ data/pm25.json（隨 Pages 部署，不 commit）
                                                                                              │
網頁「即時資料」模式 ──(fetch，加時間參數＋cache: 'no-store'，避開瀏覽器與主畫面 App 快取)──────┘
```

- 排程為每小時第 15、45 分各一次（GitHub 排程常延遲 30–90 分鐘、偶爾跳過，一小時排兩次可降低資料過期的機率）；降雨預報 50 分鐘內不重複查 Open-Meteo，不會多耗額度；`deploy-pages` 偶發「No artifacts named github-pages were found」時，會等 30 秒自動重試一次。
- 環境部整點資料約 40 分鐘後上線，第 45 分那次抓到最新資料。API 失敗時重試，仍失敗則沿用線上那份 JSON；也拿不到時（排程執行）不部署，線上維持上一版。
- **取值**：使用 `pm2.5`（最近 1 小時）；缺值、非數值或 ≤ 0 時改用 `pm2.5_avg`（移動平均），該點的**最近測站**使用移動平均值時，資訊卡註明「PM2.5 使用移動平均值」。
- **清洗**：
  1. 只採用台北範圍框向外約 10 km 內的測站（經度 121.35–121.77、緯度 24.87–25.30，約 20 站，含基隆、淡水、林口、樹林等），改善市界邊緣的估算。
  2. 排除 PM2.5 **≤ 0** 或 **> 500** μg/m³（且移動平均也無效）的測站。
  3. 排除資料時間距今超過 **3 小時**的測站（容許資料上線時間與 GitHub 排程延遲）。
  4. 有效測站 < 2 站、檔案讀不到或格式錯誤時，自動改用內建 Mock 數據，並顯示「離線／展示模式」與原因（例如「環境部資料超過 3 小時未更新（最後資料時間 22:00）」）。
- 本機開發時沒有 `data/pm25.json`，「即時資料」會降級為 Mock；如要在本機看真實資料，可用自己的金鑰執行（`data/` 已列入 `.gitignore`）：

## 判定規則、IDW 與熱力圖

### 三級門檻（連續區間）

| 指標 | 🟢 | 🟡 | 🔴 |
| :--- | :--- | :--- | :--- |
| PM2.5（μg/m³） | ≤ 15.4 | > 15.4 且 < 35.5 | ≥ 35.5 |
| 降雨機率（%） | ≤ 30 | > 30 且 ≤ 60 | > 60 |
| 紫外線指數 | ≤ 5.0 | > 5.0 且 < 8.0 | ≥ 8.0 |
| 體感溫度（°C） | 10.0–30.0 | 5.0–< 10.0 或 > 30.0–33.0 | < 5.0 或 > 33.0 |

主因指標：先比燈號，同燈號依 PM2.5 > 降雨 > 紫外線 > 體感溫度；體感溫度分過熱／過冷，建議文案不同。

### IDW（跑點與熱力圖共用 `idwEstimate`）

- 數值一律使用**全部有效測站**的反距離加權（p = 2）；最近測站 < 50 m 時直接採用該測站數值。
- 距離只決定顯示、不影響數值：最近測站 > **8 km**，熱力圖留白（市界內畫淡灰斜線）；> **5 km**，資訊卡標示「5 公里內無測站，數值以較遠測站推估」。
- 門檻依據（2026-11-23 以環境部測站實測，台北市界內約 300 m 格點到最近測站的距離）：≤ 2 km 24.0%、≤ 3 km 46.0%、≤ 5 km 84.3%、≤ 8 km 99.1%，最遠 8.71 km。若沿用 3 km，市內一半以上會留白；8 km 只留下最偏遠約 1% 的山區。

### 降雨機率圖層

- **切換**：右上角圖層按鈕 → 選單「PM2.5／降雨機率／關閉」三選一；按鈕上顯示目前圖層名稱（關閉時為「圖層」）；切換時圖例、時間滑桿與地圖圖層一起換。
- **資料流程**：`tools/fetch_rain.py` 在既有的「部署網站與 PM2.5 資料」workflow 中與 PM2.5 同一次執行，向 Open-Meteo 查詢台北市範圍的網格點（網格定義在 `index.html` 的 `CONFIG.RAIN.grid`，間距約 1.5 km，只查涵蓋市界所需的約 200 個節點，每批 50 個、分 5 批、間隔 2 秒），取「目前整點」起 15 個整點的 `precipitation_probability`，存成 `data/rain.json`（隨 Pages 部署，不 commit）。**瀏覽器不會自己查詢整個網格**，避免觸發 Open-Meteo 的 429。
  - 網頁取「現在」起最多 13 個時段（現在、+1 … +12 小時）；多存 2 個整點是為了讓檔案在產生後 2 個整點內仍有完整 13 個時段。
  - 每日呼叫量：約 200 個節點 × 每小時 1 次 ≈ 4,800 次，低於免費額度 10,000 次／日；若線上檔案在 50 分鐘內才產生，腳本會直接沿用，不再呼叫 API（避免短時間重複 push 消耗額度）。
  - Open-Meteo 失敗（429、逾時）時重試；仍失敗就沿用線上目前的 `rain.json`；沒有檔案也不會讓部署失敗。
- **網頁讀取**：讀 `data/rain.json?t=時間戳`，並設 `cache: 'no-store'`（避開瀏覽器與 iPhone 主畫面 App 的快取）。檔案產生時間超過 **3 小時**或讀取失敗、格式錯誤時，降雨圖層顯示「降雨預報暫時無法取得」（滑桿區與圖例都會提示），不影響其他功能。
- **繪製與配色**：網格點雙線性內插（缺值節點不參與），依門檻離散上色後裁切在台北市界內；透明度與 PM2.5 熱力圖相同（0.35）。四級配色（只是熱力圖的視覺分級，**跑點燈號門檻不變**：≤ 30% 仍是綠燈）：

  | 降雨機率 | 圖例文字 | 顏色 |
  | :--- | :--- | :--- |
  | < 10% | 幾乎不會下雨 | 淺白 `#E8F2FF` |
  | 10–30% | 降雨機率低 | 淺藍 `#7DB8FF` |
  | 31–60% | 可能下雨 | 中藍 `#1D6FF2` |
  | > 60% | 很可能下雨 | 藍紫 `#6D28D9`（Violet-700，色相約 263°，偏藍的紫，不是粉紫） |

  色值是依「疊在淺色底圖上的實際顏色」挑的：相鄰兩級色差（CIE76 ΔE）≥ 14；不含綠黃紅；藍紫避開 PM2.5 的紅與紅燈。「淺白」本來就接近底圖，所以降雨圖層另畫一圈台北市界細線輔助辨識範圍；它是純色塊，與 PM2.5 圖層「無資料」的灰色斜線紋理不同。靛藍的「我的最愛」星形標記疊在藍紫區上，星形填色對藍紫區的對比約 3.2:1、白色外框約 2:1，可辨識，但對比偏低，留待階段 G 一併調整。
- **時間滑桿**：只改變降雨熱力圖（顯示「+3 小時｜14:00」），跑點燈號與資訊卡仍依「目前狀況」判定，滑桿旁註明「僅顯示降雨預報，跑點燈號為目前狀況」。切到 PM2.5 或關閉時滑桿隱藏。寬螢幕在地圖下方中央；窄螢幕在 Bottom Sheet 上方（Sheet 展開時隱藏）。
- **解析度（請注意）**：網格間距約 1.5 km，但 Open-Meteo 的降雨機率來自約 27 km（0.25°）解析度的集合預報，相鄰網格點常是同一個預報格，所以畫面上會是大塊的同色區域，並在預報格交界處出現較明顯的邊界；圖例已註明「原始解析度約 27 km，僅供參考。預報以方格計算，邊界可能呈直線」。直線邊界（例如北緯約 25.125°、東經約 121.625°）是預報模型的 0.25° 方格邊界，資料本身就不連續，刻意不做柔化。
- **細小白點（已修正）**：「即時資料」模式下，網格節點同值時，內插的浮點誤差（約 1e-15）會讓剛好落在門檻（如 10%）的像素隨機被判成淺白，形成散布的白點；現已把內插結果四捨五入到 0.01 並加入回歸測試。PM2.5 熱力圖的內插值本來就取到 0.1，並以連通區塊檢查確認沒有同樣問題（已納入測試）。
- **Mock 情境**：不讀 `rain.json`，用同一組網格產生 13 個時段的模擬降雨，與跑點的降雨燈號一致：正常＝市內約 70% 為淺白（< 10%）、其餘淺藍，北部山區稍後升到 31–60%；高空汙＝全市整片淺白；大雨曝曬＝大佳與花博附近 > 60%（藍紫）、其餘 ≤ 30%，並逐時減弱（約 +5 小時降到 60% 以下、+11 小時降到 30% 以下），讓滑桿有變化可看。

### 熱力圖

- 在台北市外框的外接矩形內以 75 m 細格逐格呼叫 `idwEstimate`（不先算 300 m 網格再內插：網格節點不會剛好落在測站上，測站附近的峰值會被平均壓低一級），依門檻離散上色，再以市界裁切，用 `L.imageOverlay`（透明度 0.35）疊在地圖上。
- 圖例只描述 PM2.5 濃度高低（PM2.5 低／中／高），不使用跑點燈號用語，避免「紅色不建議前往標記」壓在「適合出發」綠區上的矛盾。窄螢幕預設為單行小圖例，點一下展開完整說明。
- 只在資料更新時重算（Chrome CPU 4× 降速下，30／80／150 站分別約 0.1／0.2／0.3 秒）；開關只切換圖層顯示。

## 背景監測與通知

- 預設關閉。開啟時請求通知權限；被拒絕、不支援（例如網址不是 HTTPS／localhost）時改為只顯示頁面橫幅，並說明原因。
- 每 10 分鐘（隨資料更新；手動切換資料模式也會立即檢查）比較「目前位置」的燈號：**綠 → 黃/紅、黃 → 紅** 時提醒；第一次檢查只記錄基準。沒有定位顯示「需定位才能監測」。
- 提醒內容為狀態、主因與建議，同時送出系統通知與可關閉的橫幅（最多同時 3 則）。
- 同一行政區 60 分鐘內不重複提醒；冷卻紀錄存於 `localStorage`（不可用時退回記憶體）。「立即測試通知」同樣遵守冷卻，冷卻中顯示「冷卻中，剩 N 分鐘」；「清除冷卻紀錄」可重置。沒有定位時，測試通知以選取的跑點（或第一個跑點）示範。
- 想快速看到效果：開啟監測後（需有定位），把資料模式從「正常」切到「高空汙」。
- **`sw.js`**：手機瀏覽器（Android Chrome、iOS）不允許頁面直接 `new Notification`，必須經由 Service Worker 的 `showNotification`，所以多了一個只負責顯示通知與點擊回到頁面的 `sw.js`（不快取、不攔截請求）。`file://` 無法註冊 Service Worker，會自動退回頁面直接通知或橫幅。

### iPhone 通知設定

需 **iOS 16.4 以上**：先用 Safari 開啟網址 →「分享 → 加入主畫面」→ 從**主畫面圖示**開啟（以 App 方式運作）→ 設定選單開啟背景監測並允許通知。在 Safari 分頁內無法使用系統通知（頁面內橫幅仍可用，介面會提示）。

專案含 `manifest.json`（standalone、主題色 #10B981、背景色 #F8FAFC）與 `icons/`（192／512／apple-touch-icon）。manifest 只在 http(s) 下動態加入；`file://` 不載入，以免 Chrome 在 Console 印出 CORS 錯誤。

## 已知限制

- **頁面關閉後無法監測**：純網頁在分頁／App 被關閉後無法執行。iOS 上 App 切到背景後網頁很快被凍結，計時器與 Service Worker 都無法長時間運作，回到前景時才會補做檢查。
- **PM2.5 測站稀疏**：環境部台北周邊約 20 站，市內只有 46% 的位置在 3 km 內有測站，熱力圖較平滑、無法反映街區尺度差異；資料每小時更新一次，並有約 1 小時的上線延遲。
- **CARTO 金鑰已限制網域**：只有 GitHub Pages 網址能載入底圖；`file://` 與 `localhost`（除非也加入允許清單）會看到空白底圖，Console 會出現底圖圖磚的 `403`。開發與 Demo 請用 GitHub Pages 網址。
- **Console 已知錯誤**：由瀏覽器網路層直接輸出，網頁程式無法攔截；程式已自動降級。在 GitHub Pages 上，三種 Mock 情境的 Console 應為零錯誤、零警告。

  | 錯誤訊息 | 來源 | 原因 |
  | :--- | :--- | :--- |
  | `403` 圖磚（`*.basemaps.cartocdn.com`） | CARTO 底圖 | 金鑰已限制在 GitHub Pages 網域，`file://`／未列入的 `localhost` 會被拒絕（任何模式） |
  | `data/pm25.json` 的 CORS 錯誤 | 環境部資料檔 | 只在以 `file://` 開啟並切到「即時資料」時出現（`file://` 不允許 fetch 本機檔案） |
  | `429 (Too Many Requests)` | Open-Meteo | 同一對外 IP 請求過多被限流（雲端主機、共用網路較常見，通常稍後即恢復） |
  | `data/rain.json` 的 CORS 錯誤 | 降雨預報檔 | 只在以 `file://` 開啟、切到「即時資料」並選降雨圖層時出現（同 `data/pm25.json`） |
  | CORS 錯誤／`629` 或 `429` | Nominatim（地點搜尋） | 只會在使用「搜尋地點」且被限流或用 `file://` 開啟時出現；被限流時錯誤頁不含 CORS 標頭，介面會顯示查詢失敗訊息 |

- **地點搜尋依賴公用服務**：容量有限、需 Referer（`file://` 不可用），詳見上方使用定位聲明。
- **行政區判定與市界為近似值**：行政區取最近中心點，市界簡化到約 80 m，皆不是官方界線。
- **熱力圖只反映 PM2.5**：跑點燈號看四項指標，兩者不一定一致（圖例已明講）。
- **Mock 數據僅供展示**：「正常」情境的青年公園周邊、「高空汙」情境的大佳河濱公園周邊測站數值，為了讓熱力圖在跑點附近形成肉眼可見的紅／黃色區塊而刻意調整（跑點本身的燈號不變）。
- **最愛只存在單一瀏覽器**：沒有匯出入或帳號同步；清除瀏覽器網站資料、換瀏覽器或換手機都不會帶著走。
- **iOS 通知需加入主畫面**；iOS 版本需 16.4 以上；通知無法保證在背景持續監測期間送達。

## 未來可擴充項目

1. **我的最愛的延伸**：匯出／匯入、背景監測改為監測最愛、帳號同步（隨階段 H 後端）。
2. **伺服器 Web Push**：讓 App 完全關閉也能收到通知。需要 VAPID 金鑰、Service Worker `push` 事件、前端訂閱流程，以及後端（儲存訂閱與粗略位置、每 10 分鐘抓資料並套用同一套判定、用加密 Web Push 協定送出）。免費方案可考慮 Cloudflare Workers＋Cron Trigger＋KV/D1。需評估隱私（儲存裝置端點與位置，建議只存行政區代碼並設保存期限）與維運成本，預估 3–5 個工作天（含 iOS 實機除錯）。
3. **更密的 PM2.5 資料**：環境部測站稀疏；未來可評估加入微型感測器資料（需確認來源、品質與授權）以提高解析度。
4. **擴充到台灣北部**：把 `RUN_SPOTS` 擴充到 25 個以上並涵蓋新北、基隆、桃園；市界改為多個縣市界或改用行政區面資料；`BBOX`、行政區判定與 `CONFIG.GEOCODER` 的範圍同步調整。
5. **更精確的行政區判定**：用官方行政區面資料（例如內嵌簡化後的 12 區多邊形）取代最近中心點。
6. **跑點評分與路線**：加入空氣品質預報、依時段推薦出發時間，或與路線資料結合。
7. **更多氣象來源與備援**：中央氣象署開放資料（需金鑰）作為 Open-Meteo 的備援。

## 測試與專案結構

在瀏覽器 Console 執行：

```js
SafeAir.runTests()
```

會測試四項指標的門檻邊界值、總體判定、缺值處理、主因優先順序、推薦規則、熱力圖與跑點／`idwEstimate` 的一致性（含固定種子抽 50 個市界內座標）、長按偵測、行政區判定、監測轉差規則、冷卻、地圖選點與市界外處理，以及狀態文字色的 WCAG AA 對比度，並回報通過數。也可單獨呼叫：

```js
SafeAir.evaluate({ pm25: 12, rain: 40, uvi: 9, feels: 25 })
```

```
index.html      # 全部 HTML / CSS / JavaScript（內嵌，依功能分段註解）
sw.js           # Service Worker：只負責顯示通知（手機瀏覽器需要）
manifest.json   # PWA 設定（加入主畫面後以 App 方式開啟）

README.md       # 本文件
tools/fetch_moenv.py   # 環境部 AQI → data/pm25.json（GitHub Actions 每小時執行）
tools/fetch_rain.py    # Open-Meteo 降雨機率網格 → data/rain.json（與 PM2.5 同一個 workflow、同一次執行）
tools/moenv_probe.py   # 環境部 API 探測（只輸出摘要；手動 workflow 使用）
tools/pm25_summary.py  # LASS 資料欄位摘要腳本（LASS 已停用，保留參考）
.github/workflows/pages.yml        # 部署網站＋抓取 PM2.5（push、每小時第 15／45 分、手動；部署失敗自動重試一次）
.github/workflows/moenv-probe.yml  # 環境部 API 探測（只能手動）
```
